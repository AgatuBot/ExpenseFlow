## 1. Project Introduction

ExpenseFlow is a practical AI agent development project created to explore how to build an intelligent application using Python, Microsoft Agent Framework and language models.

The goal was to develop an expense claim assistant capable of understanding user requests, calling a custom Python tool and checking expense claims against predefined policy limits.

The project also provided an opportunity to learn how to connect AI models, build a web interface, test application behaviour and deploy a working application.

## 2. Development Environment

The development environment includes:

- Windows and PowerShell
- Python 3.13
- Python virtual environment
- Microsoft Agent Framework
- Ollama
- Qwen2.5 3B
- Flask
- HTML, CSS and JavaScript
- Git and GitHub
- Render

## 3. Setting Up the Local AI Environment

I began by preparing the Python development environment and installing the packages required for the application.

I configured Ollama to run a language model locally and downloaded Qwen2.5 3B.

This provided a way to experiment with an AI agent without depending entirely on paid cloud AI services.

**Key learning:** A language model provides the conversational capability, while application code and tools provide additional functionality and control.

## 4. Building the Expense Claim Agent

The next stage involved developing the AI agent in Python.

The agent was designed to understand expense-related questions and use a custom validation tool when checking claims.

The project uses Microsoft Agent Framework to support agent development and tool integration.

**Key learning:** An AI agent can use a tool to perform a defined operation rather than relying only on information generated by the language model.

## 5. Developing the Expense Policy Tool

I created a custom Python policy validation tool in:

`src/policy_tools.py`

The tool checks an expense category and claimed amount against configured limits.

The current simulated policy is:

| Category | Policy Limit |
|---|---:|
| Transport | ₦50,000 |
| Meals | ₦30,000 |
| Accommodation | ₦150,000 |
| Other | ₦25,000 |

The tool identifies whether a claim is within its configured limit or exceeds it.

It also validates input values to help prevent invalid amounts and categories from being processed.

**Key learning:** Custom tools allow an AI agent to interact with structured application logic and return results based on defined rules.

## 6. Connecting AI Model Providers

I expanded the application to support different AI model providers.

The configurations include:

- Ollama for local model execution.
- Groq for hosted model access.
- Gemini for hosted model access.

The selected provider is controlled through environment configuration.

API credentials are stored locally or in the hosting platform's environment settings rather than being included in the source code.

**Key learning:** An application can be designed to work with different model providers while keeping its main application and tool logic separate.

## 7. Building the Web Interface

I developed a Flask web application to provide a conversational interface for ExpenseFlow.

The frontend uses HTML, CSS and JavaScript.

The interface was refined with a professional navy and teal design, including the AgatuBot branding.

The application provides:

- An overview dashboard.
- An AI assistant interface.
- An expense policy page.
- A conversational claim validation experience.

**Key learning:** A useful AI application requires more than a working model. It also needs an interface through which people can interact with it.

## 8. Testing and Improving Agent Responses

I tested the application using different expense claim amounts.

Examples included:

| Test | Expected Result |
|---|---|
| Transport claim of ₦35,000 | Within the ₦50,000 limit |
| Transport claim of ₦50,000 | Within the limit, with zero remaining allowance |
| Transport claim of ₦60,000 | Exceeds the limit by ₦10,000 |
| Accommodation claim of ₦160,000 | Exceeds the limit by ₦10,000 |

During testing, I identified cases where the AI could interpret the difference incorrectly or make unsupported statements about approval and payment.

I refined the agent instructions to distinguish between remaining allowance and excess amounts.

I also added safeguards to prevent the agent from claiming that a result automatically approves, rejects or pays an expense claim.

**Key learning:** Testing an AI agent involves checking not only whether its tools return correct results, but also whether the agent explains those results accurately and avoids inventing procedures.

## 9. Deployment

I prepared the Flask application for hosting and deployed it using Render.

https://expenseflow-4jsn.onrender.com/
